# 无人机接入进度与下一步清单

> 更新时间：2026-08-07  
> 当前阶段：普通点餐/外卖主链路基本验收完成，开始进入无人机接入准备阶段。

## 1. 当前结论

现阶段不要急着接真实无人机硬件。当前更合理的目标是先把“订单 -> 配送任务 -> 推荐配送点 -> 生成航点文件 -> Mission Planner 校验”的软件链路跑顺。

已经完成的关键点：

- 小程序普通下单链路已能创建订单，真实支付环境缺失导致支付异常属于预期限制。
- 管理端配送任务已从真实外卖订单派生，不再完全依赖静态 mock。
- 无人机状态仍保留 mock，符合当前没有真实硬件接入的 MVP 阶段。
- 后端已能生成 `QGC WPL 110` 格式航点文件。
- Mission Planner 已能导入生成的航点文件，并识别为 TAKEOFF / WAYPOINT / LAND。
- 配送点推荐已从 Java mock 改为 MySQL 表 `app_delivery_point`。
- 小程序结算页已修复门店/购物车缓存状态问题，避免无门店下单。

目前能说明的是：航点文件格式和管理端生成流程基本可用。  
目前还不能说明的是：真实无人机能够安全、稳定、按该航点完成配送飞行。

## 2. 已验证内容

### 2.1 小程序下单

- 可以从点餐页选择商品进入结算。
- 结算页可以恢复门店、购物车、订单类型。
- 订单创建接口能够返回 `orderId`。
- 微信支付没有真实环境时返回系统异常，不作为当前阻塞项。

### 2.2 管理端配送任务

- 配送任务列表可以展示真实订单派生出的待配送任务。
- 任务中包含订单号、取货站点、送达地址、状态等信息。
- 无人机状态区域仍为模拟数据，仅用于界面占位。

### 2.3 航点文件生成

- 管理端可以打开“航点”弹窗。
- 可以根据订单填写或推荐配送点坐标。
- 可以预览 `QGC WPL 110` 文件内容。
- 文件结构目前为：

```text
HOME / 起点
TAKEOFF / 起飞
WAYPOINT / 巡航到目标点
LAND / 降落
```

- Mission Planner 可以导入该文件并显示航点路径。

### 2.4 配送点推荐

- 已新增 `app_delivery_point` 表。
- 已提供 `docs/database/delivery-points.sql` 初始化脚本。
- 推荐逻辑目前是：从启用的配送点中，按用户坐标计算最近点。
- 当前配送点数据仍是占位数据，后续需要实地采集和无人机组验证。

## 3. 尚未验证内容

这些内容不能靠当前软件系统单独确认：

- 真实飞控是否接受该航点文件。
- Mission Planner “写入航点”到飞控后的真实行为。
- 起飞高度、巡航高度、降落高度是否安全。
- GPS 偏差、电压波动、风、遮挡等因素下的偏航表现。
- 真实降落点是否有足够安全半径。
- 无人机是否具备自动避障能力。
- 电池电量和载重是否支持完整往返。
- 学校/园区是否允许对应路线飞行。
- 紧急中止、返航、失联、低电量等流程。

## 5. 下一步开发顺序

建议按下面顺序继续：

1. 配送点管理页面  
   目标：不用手写 SQL，在管理端维护配送点。

2. 配送点字段完善  
   目标：支持启用/禁用、是否已验证、默认高度、安全备注。

3. 航点生成参数完善  
   目标：允许按配送点默认高度生成航线，并保留人工覆盖。

4. 与无人机组确认真实飞行参数  
   目标：确认格式、上传方式、高度、半径、载重、电量策略。

5. 小范围地面/静态验证  
   目标：先不飞，确认 Mission Planner 写入和飞控读取行为。

6. 小范围空载飞行测试  
   目标：只验证航线，不携带餐品。

7. 小范围载重飞行测试  
   目标：验证载重、耗电、降落稳定性。

## 6. 需要向无人机组确认的问题

- 现在最终使用的飞控是什么型号？
- 固件是不是 ArduPilot？版本是多少？
- 是否确定使用 Mission Planner 导入和写入航点？
- 他们提供的 `.waypoints` 示例是否就是最终格式？
- 起飞点是否固定在门店附近？
- 降落点是否只能选固定点，还是允许任意用户地址附近？
- 推荐巡航高度是多少？
- 最大安全飞行距离是多少？
- 最大安全载重是多少？
- 是否有自动避障能力？
- 如果 GPS 漂移、风吹偏、电压不稳，无人机会自动修正到航线吗？
- 低电量时是降落、悬停、返航，还是人工接管？
- 失联时是返航还是原地降落？
- 测试时是否允许我们只生成文件，由无人机组负责导入和执行？

## 7. 当前推荐判断

短期内不要做“全自动无人机调度”。  
当前最务实的交付目标是：

```text
真实订单
  -> 管理端配送任务
  -> 推荐固定配送点
  -> 生成 Mission Planner 航点文件
  -> 人工检查
  -> 人工写入飞控
  -> 无人机组执行测试
```

这样风险最低，也最符合当前资料和硬件条件。
