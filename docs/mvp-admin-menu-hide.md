# 香农之翼 MVP 阶段 - 管理端菜单隐藏说明

## 一、为什么第一阶段只隐藏菜单，不删除代码

1. **风险可控**：隐藏菜单只是将 `visible` 设为 `0`，不涉及代码删除，出问题可快速回滚
2. **依赖保护**：部分功能虽然 MVP 不需要，但底层可能被其他模块依赖（如站点管理）
3. **快速迭代**：隐藏入口即可达到"不可见"效果，无需等待代码裁剪完成
4. **保留选项**：未来如需恢复某功能，只需将 `visible` 改回 `1`，无需重新开发

## 二、为什么只改 visible，不改 status

| 字段 | 含义 | 修改影响 |
|------|------|----------|
| `visible` | 是否在侧边栏显示 | 只影响菜单可见性，不影响权限判断 |
| `status` | 菜单状态（启用/停用） | 可能影响权限校验、路由生成等逻辑 |
| `deleted` | 是否删除 | 逻辑删除，影响数据完整性 |

**结论**：修改 `visible` 是最安全的隐藏方式，不会影响权限系统和路由逻辑。

## 四、如何回滚

### 方式一：从备份表恢复

```sql
-- 从备份表恢复
UPDATE system_menu m
INNER JOIN system_menu_backup_20260519 b ON m.id = b.id
SET m.visible = b.visible;
```

### 方式二：直接恢复所有隐藏的菜单

```sql
-- 恢复所有被隐藏的菜单

SET visible = b'1'
WHERE id IN (
```

```sql

```

## 五、注意事项

1. **不要直接删除数据库记录**：所有隐藏操作只修改 `visible` 字段
2. **不要修改 `status` 字段**：避免影响权限系统
3. **不要修改 `deleted` 字段**：保持数据完整性
4. **执行前务必备份**：确保可回滚
5. **子菜单自动隐藏**：SQL 中已包含子菜单的隐藏逻辑
6. **权限不变**：隐藏菜单不会影响已分配的权限，只是入口不可见
